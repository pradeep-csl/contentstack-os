# Multi-workspace Context Collections Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a Context Library collection be scoped to several workspaces at once, so one collection can serve `gtm1` and `gtm2` without duplication or swapping.

**Architecture:** Widen the single-valued workspace scope to a set, in place. The scope stays a field on the owner-library record — no new Durable Object, no new binding, no data migration. Legacy single-valued records are normalized on read and rewritten in the new shape the next time they are touched. `visibility` stays a faithful projection of the set: empty → `private`, non-empty → `workspace`, and "workspace" continues to mean *only* those workspaces.

**Tech Stack:** TypeScript, Cloudflare Workers + Durable Objects, `@gadgets/typed-storage`, Cap'n Web RPC (`capnweb`), Vitest (two suites: Node via `vitest.config.ts`, Workers pool via `vitest.workers.config.ts`), React + Kumo for the gatekeeper app.

**Spec:** [`docs/superpowers/specs/2026-08-30-multi-workspace-context-collections-design.md`](../specs/2026-08-30-multi-workspace-context-collections-design.md)

## Global Constraints

- **pnpm only.** Never `npm`. Package filter: `pnpm --filter @gadgets/gatekeeper-context`.
- **Both test suites must pass.** `pnpm --filter @gadgets/gatekeeper-context test:run` runs `vitest run` (Node) *and* `vitest run -c vitest.workers.config.ts` (Workers pool). A change that only passes one is not done.
- **Zero kernel diff.** Do not modify `packages/workshop-shared` or `packages/workshop-backend`. Do not modify `packages/workshop-frontend` — `pickWorkspace()` and `resolveWorkspaceTitles()` already have the needed shapes.
- **No `wrangler.jsonc` change, no new Durable Object class, no migration tag.** If you find yourself adding one, stop: the design is wrong somewhere.
- **Exclusivity copy is load-bearing.** Any user-facing description of workspace scope must keep the "and only there" clause. A collection scoped to workspaces is readable *only* in them, never in the owner's other workspaces.
- **Caps:** `MAX_SCOPED_COLLECTIONS_PER_WORKSPACE = 50` (existing, unchanged), `MAX_WORKSPACES_PER_COLLECTION = 20` (new).
- **Workspace id shape:** `/^[0-9a-f]{64}$/`. Validate at the API boundary only; Durable Objects stay unvalidated because a malformed scope there is only ever unreadable, never a grant.
- **Never write the legacy field again.** `scopedToWorkspace` is read-only from Task 2 onward, and is explicitly cleared on conversion so a record can never carry two disagreeing scopes.
- **No AI/LLM attribution in commit messages.** No `Co-Authored-By`.
- **Do not `git add` anything under `docs/superpowers/`.** Stage files explicitly by name; never `git add -A`.

```ts
/**
 * Whether an owned collection is readable by an agent acting in `workspaceId`. An unscoped
 * collection is readable everywhere; a scoped one only in the workspaces it lists. Passing no
 * `workspaceId` (a caller with no workspace context) excludes every scoped collection.

 * caller id could never equal an absent scope by accident, but `includes()` would match a list that
 * somehow held `undefined`.
 */
export function isVisibleInWorkspace(
    scopes: string[] | undefined, workspaceId: string | undefined): boolean {
  return !scopes?.length || (!!workspaceId && scopes.includes(workspaceId));
}
```

```ts
type OwnedRecord = {
  id: string;
  title: string;
  description: string;
  icon?: string;
  // The workspaces this collection is scoped to; absent or empty means "enabled everywhere".
  scopedToWorkspaces?: string[];
  /**
   * @deprecated Written only by builds predating multi-workspace scope. Read through
   * `recordScopes()`, never written again, and cleared whenever a record is rewritten — so a record
   * can never carry two disagreeing scopes.
   */
  scopedToWorkspace?: string;
  lastUpdated: Date;
};

/**
 * The workspaces an owned record is scoped to. Records written before multi-workspace scope carry
 * the legacy single-valued `scopedToWorkspace`; they read as a one-element set and are rewritten in
 * the new shape the next time the record is touched. An explicitly empty `scopedToWorkspaces` wins
 * over a legacy value, so clearing a scope is never undone by a stale field.
 */
export function recordScopes(
    record: {scopedToWorkspaces?: string[]; scopedToWorkspace?: string}): string[] {
  if (record.scopedToWorkspaces) return record.scopedToWorkspaces;
  return record.scopedToWorkspace ? [record.scopedToWorkspace] : [];
}
```

```ts
  createOwnedCollection(
      id: string, title: string, description: string, icon?: string,
      scopedToWorkspaces?: string[]): void {
    for (let workspaceId of scopedToWorkspaces ?? []) this.#assertScopeBudget(workspaceId);
    this.storage.ownedCollections.put({
      id, title, description, icon,
      scopedToWorkspaces: scopedToWorkspaces?.length ? scopedToWorkspaces : undefined,
      lastUpdated: new Date(),
    });
  }

  // Bounds one workspace's enabled set; see MAX_SCOPED_COLLECTIONS_PER_WORKSPACE.
  #assertScopeBudget(workspaceId: string): void {
    let count = 0;
    for (let record of this.storage.ownedCollections.list()) {
      if (recordScopes(record).includes(workspaceId)) count++;
    }
    if (count >= MAX_SCOPED_COLLECTIONS_PER_WORKSPACE) {
      throw new RangeError(
        `This workspace already has too many Context collections ` +
        `(limit ${MAX_SCOPED_COLLECTIONS_PER_WORKSPACE}).`);
    }
  }

  /** Refresh the denormalized owned record, including its workspace scopes. */
  updateOwnedCollection(id: string, summary: ContextCollectionSummary): void {
    let record = this.storage.ownedCollections.get(id);
    if (!record) return;
    record.title = summary.title;
    record.description = summary.description;
    record.icon = summary.icon;
    // Only workspaces this record is *newly* entering consult the budget. #propagate()
    // (context-collection.ts) calls this on every metadata edit with the collection's existing,
    // unchanged scopes; counting those against their own workspaces' budgets would wrongly reject a
    // routine edit once a workspace holds exactly the cap. Leaving a workspace never needs it either.
    let existing = new Set(recordScopes(record));
    let next = summary.workspaceIds ?? [];
    for (let workspaceId of next) {
      if (!existing.has(workspaceId)) this.#assertScopeBudget(workspaceId);
    }
    // Carried explicitly: this method rebuilds the record from the summary, so omitting it would
    // silently drop the scopes on the next metadata edit. The legacy field is cleared here, which is
    // what converts a pre-multi-workspace record.
    record.scopedToWorkspaces = next.length ? next : undefined;
    record.scopedToWorkspace = undefined;
    record.lastUpdated = summary.lastUpdated;
    this.storage.ownedCollections.put(record);
  }
```

```ts
  /**
   * Set the exact workspaces this collection is scoped to; an empty list returns it to private.
   * Propagation carries the new scopes into the owner-library record, which is what actually enables
   * the collection in those workspaces — and, for a workspace whose scope was removed, what lets it
   * take collaborators again. Callers reject public collections first (they have no owner library to
   * hold a scope).
   */
  async setWorkspaceScopes(workspaceIds: string[]): Promise<void> {
    // getMetadata(), not storage.metadata.get(): a pre-multi-workspace record's scope lives in the
    // legacy field, and reading raw would treat it as unscoped and drop it.
    let meta = this.getMetadata();
    // Annotated, not inferred: a bare ternary widens to `string` and will not satisfy the field.
    let wanted: ContextCollectionVisibility = workspaceIds.length ? "workspace" : "private";
    // Compare visibility too, mirroring the guards this replaces: an early return must never skip a
    // repair of a record whose visibility and scopes disagree.
    if (meta.visibility === wanted && sameScopes(meta.workspaceIds, workspaceIds)) return;
    this.storage.metadata.put({
      ...meta,
      visibility: wanted,
      workspaceIds: workspaceIds.length ? workspaceIds : undefined,
      // Cleared on every write, so a converted record can never carry two disagreeing scopes.
      workspaceId: undefined,
      lastUpdated: new Date(),
    });
    try {
      await this.#propagate();
    } catch (err) {
      // Propagation is where the per-workspace cap is enforced and where the owner-library record —
      // the thing the enabled set actually filters on — is written. A failure must not leave metadata
      // advertising a scope the library never recorded, and restoring it also keeps the idempotent
      // early return above from reporting a retry as a success that never happened.
      this.storage.metadata.put(meta);
      throw err;
    }
  }
```

```ts
// Scopes compare as sets: a reordered list is the same scope, so it must not count as a change.
function sameScopes(left: string[] | undefined, right: string[]): boolean {
  let a = left ?? [];
  if (a.length !== right.length) return false;
  let seen = new Set(a);
  return right.every(workspaceId => seen.has(workspaceId));
```

Replace the single-id effect (~2696-2715) with one that resolves the whole list. Keep the tri-state (`undefined` = in flight) — the existing comment explains why: naming the workspace is the only claim the Access field can make, and "no longer available" is not it while a lookup is outstanding.

```ts
  const scopedWorkspaceIds = metadata?.workspaceIds;
  // Titles positionally match scopedWorkspaceIds; `undefined` means "still resolving", and a `null`
  // entry means that one workspace is gone. A deleted workspace must not make its siblings
  // unnameable, so the array is resolved as a whole and rendered per entry.
  const [workspaceTitles, setWorkspaceTitles] =
    useState<(string | null)[] | undefined>(undefined);
  useEffect(() => {
    setWorkspaceTitles(undefined);
    if (!scopedWorkspaceIds?.length) return;
    let cancelled = false;
    resolveWorkspaceTitles(scopedWorkspaceIds)
      .then((resolved) => {
        if (!cancelled) setWorkspaceTitles(resolved);
      })
      .catch(() => {
        if (!cancelled) setWorkspaceTitles(scopedWorkspaceIds.map(() => null));
      });
    return () => {
      cancelled = true;
    };
    // Joined so a re-render with an equal-but-new array does not re-resolve.
  }, [scopedWorkspaceIds?.join(","), resolveWorkspaceTitles]);
```

## Deliberately out of scope

Do not implement these; they are recorded in the spec's §10 and each needs its own design:

- Scoping into a workspace owned by another user (structurally impossible today — a workspace reads its *owner's* library).
- Cross-account grants / sharing with specific people (blocked on gatekeepers having no identity).
- `private` ↔ `public` transitions after creation (blocked on public collections having `ownerAccountId: ""`, and on `public` becoming a revocable observation ground).
- Teams as a Workshop primitive.
- Multi-select at create time — the create dialog keeps its single-workspace pick.
